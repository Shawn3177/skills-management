# 项目级技能部署

在现有 Windows 桌面应用中增加“项目”入口。用户选择并保存项目目录，查看共享库在该项目的部署状态，将技能部署到工具正式支持的项目目录，或将项目已有技能导入共享库。

## 作用域与界面

- 第一版支持 Codex `.agents/skills`、Claude Code `.claude/skills`、VS Code `.github/skills`。目录依据各工具官方文档核对。
- 共享库继续作为技能来源。项目部署为独立快照，显示已部署、待同步、本地修改和目录冲突。更新共享库后由用户在项目页选择同步，避免正在进行的项目自动切换技能版本。
- 项目页复用现有字体、按钮、列表和 Lucide 图标。顶部选择项目并展示完整路径，主体提供共享库部署和项目已有技能导入。移除项目记录仅停止管理该目录。
- 项目目录登记在本机数据根目录，重启后可继续选择。文件操作全部通过串行 Rust 写入命令执行。

## 文件安全

- 校验注册目录及目标路径，拒绝用户主目录、应用数据目录和经过符号链接或 Windows junction 的目标。
- 项目副本记录来源和部署时内容指纹。未托管的同名目录显示冲突；本地修改的已托管副本可以先导入共享库保存，也可以明确确认后备份并同步或移除。确认绑定扫描时的内容指纹，确认后再次变化则中止操作。
- 在目标盘内准备新副本，再备份旧副本到应用回收站，使用同盘重命名切换。失败时恢复旧目录。此流程需要覆盖项目与数据根目录处于不同盘符的情况。
- 项目副本独立于共享库生命周期。删除共享库技能后，其项目副本仍可读取和重新导入。

## 实施与验证

1. 增加项目注册、扫描与部署服务，复用技能扫描、兼容检查、复制排除规则和托管标记。
2. 增加 Tauri 命令和项目页面，接入中英文、加载/错误反馈与键盘操作。
3. 增加针对作用域隔离、持久化、冲突、内容修改、回滚和路径跳转的回归测试。
4. 执行 Rust 测试、前端测试和构建，检查浏览器界面并运行桌面应用。

基线 Rust 测试通过 122 项，跳过 7 项网络测试。前端通过 78 项，`partitionSkills` 有一项依赖系统区域设置的排序断言失败。

本机未找到 `design-taste-frontend`，本次读取了 taste-skill 官方仓库中的同名技能。按项目的界面约定沿用现有设计系统。Product Design get-context 已确认目标与使用场景。

官方目录依据见 [Codex](https://learn.chatgpt.com/docs/build-skills)、[Claude Code](https://code.claude.com/docs/en/skills) 和 [VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills)。

## 验证结果

- `cargo test`：128 项通过，7 项依赖 GitHub 网络的测试按原设置跳过；`cargo check` 通过。
- `npm run build`：通过。Vite 提示主 JS 包超过 500 kB，不影响构建。
- `npm test -- --run src/components/ProjectsView.test.tsx src/App.test.tsx src/i18n/messages.test.ts`：61 项通过。全量前端测试 83 项通过，1 项仍为上述基线排序断言失败。
- 通过隔离数据目录运行真实 Tauri / WebView2 应用，以 Playwright 操作项目页：部署、共享库更新后手动同步、本地修改确认、停用、项目技能导入、目录冲突、重新载入项目记录、移除记录后保留文件均通过。
- 实际项目位于 D 盘，应用数据及备份位于 C 盘，确认更新前的文件和本地新增文件保留在备份中。
- 840×580 和 1100×800 界面无横向溢出，搜索与键盘焦点正常。测试数据未写入用户的真实技能库。
- 添加已有项目的目录别名时，以后端返回的规范路径选中项目，避免选错部署目标；已添加回归测试。
